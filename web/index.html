Spec-Driven Development

Specs in. Predictable boards out.

Pair iKanban with a spec-driven workflow to turn requirements into a reviewable plan, then into cards that any developer — or low-cost model — can execute safely.

  1. Spec Intent and acceptance criteria
  2. Tasks Small, ordered steps
  3. Board Reviewable YAML cards
  4. Code Scoped, validated changes

Clear acceptance criteria

Specs and tasks define “done” before code changes, and the board mirrors that plan.

Reviewable artifacts

Every spec change and card move is a text diff, so reviews stay concrete and traceable.

Smaller, cheaper prompts

Structured tasks give low-cost models the context they need without massive prompts.

Safer edits

Explicit scope and validation reduce speculative changes and accidental overwrites.

A good fit for low-cost models

A model such as DeepSeek V4.1 Flash 1017 can follow structured specs and task lists to manage the board at a fraction of the cost of larger models — while you keep review and approval in the loop.

Installation

Start now, your way.

iKanban is distributed through the repository. Download the VSIX to use the extension or run the source to contribute.

Fastest path

Use the extension

Download the latest .vsix from the repository page and install it in VS Code.

  1. Open the Extensions view in VS Code.
  2. Click ··· and choose Install from VSIX….
  3. Select the downloaded file and run iKanban: Initialize Board.
Open repository

Run from source

Clone the project, install dependencies and open it in VS Code to run from source.

terminal 
git clone https://github.com/igorsantos314/ikanban-vscode-extension.git
cd ikanban-vscode-extension
npm install
npm run build

Then open the folder in VS Code and press F5 to launch the Extension Development Host.

Requires VS Code 1.147 or newer and a trusted workspace for writing board files.

FAQ

Frequently asked questions.

The essentials for understanding how iKanban stores, moves and protects your work.

Is iKanban free?

Yes. The project is open source under the MIT license. You can use, study, modify and distribute it.

Do I need an account or internet?

No. The board works offline and has no login, sync or server. Your files stay in the workspace.

Where is my data stored?

In .ikanban/, next to your code: board.yaml, one folder per column and one YAML file per task.

Can I use it with Git?

That is the point. Every card is a text file, so commits and pull requests show exactly what changed on the board.

Can I edit the YAML by hand?

Yes. iKanban validates files and watches for external changes. Operations use revisions to avoid overwriting manual edits.

How does the AI integration work?

iKanban ships a portable SKILL.md that any local LLM or coding assistant with workspace access can read. Install it with iKanban: Install AI Skill; no hosted AI service or model API key is required.

Why use iKanban with SDD?

Spec-driven development turns intent into reviewable specs and tasks, and the board mirrors that plan in plain YAML. That structure makes low-cost models such as DeepSeek V4.1 Flash 1017 more predictable while keeping human review and approval in the loop.
